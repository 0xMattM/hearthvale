# Overview

Welcome to the official Project Bible.

This repository contains the design, technical architecture, development strategy, and long-term vision of the project.

It is the single source of truth for everyone involved in development.

The documentation is intended for:

- Designers
- Programmers
- Artists
- Writers
- QA Engineers
- DevOps Engineers
- Community Managers
- Project Managers
- External Contributors

---

# Documentation Goals

The Project Bible aims to:

- Define a clear vision.
- Standardize development.
- Improve collaboration.
- Preserve design decisions.
- Support long-term scalability.

# Source Of Truth Rules

When topics overlap, use this priority:

1. **Vision / pillars / design rules** (`01_project_foundation`) override feature docs.
2. **System design docs** (e.g. `Economy.md`, `Combat.md`) override catalog lists.
3. **Technical architecture** docs override informal implementation notes.
4. **Changelog + Open Questions** track decisions and unresolved items.

Do not create parallel folder trees (`01-Vision` vs `01_project_foundation`). New docs must use the numbered `_` structure above.

---

# Documentation Rules

Every document should:

- Have a clear purpose.
- Follow the established structure.
- Use consistent terminology (English, PascalCase file names).
- Reference related documents when appropriate.
- Remain version controlled.

---

# Versioning

The Project Bible follows Semantic Versioning.

```
Major.Minor.Patch
```

Individual documents may remain `Draft` / `0.1.0` while the Bible structure itself is versioned here and in the Changelog.

---

# Change Management

Major changes require:

- Design review.
- Technical review.
- Documentation update.
- Changelog entry.

---

# Guiding Philosophy

> Build a living world that players enjoy inhabiting for years.

Every system should contribute toward that goal.

---

# Final Statement

The Project Bible represents the collective knowledge, vision, and technical foundation of the project.

It should evolve alongside development while preserving consistency, quality, and long-term direction.
